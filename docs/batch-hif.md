# H.I.F 批量育成（代理操作）

用于在同一对话中反复执行同一份本战路线。工具保存进度、跳过已识别的动画、处理 AP 药；对话代理按当前交接文件处理开局导航、换卡、客制化、购买和回忆。停掉任何仍在操作游戏的脚本，再使用批量工具点击。

在仓库根目录使用 `.venv/bin/python tools/batch_hif.py --batch <批次ID> <命令>`。选择当前对话唯一且固定的批次 ID。用户给出总次数后立即执行 `init <总次数>`。总次数包含首局，文件在 `reports/batches/<批次ID>.json`，已有文件不能重新初始化。

1. 首次按交接文件核对实时画面与坐标、实际 AP、快进和跳过选项、偶像及回忆。全部通过后，执行 `preflight --ap <实测值> --idol <偶像> --memory <已核对回忆>`。这条命令记录代理已做完的检查。
2. 每次用 `status` 读磁盘，再用 `begin` 登记局号后开局。首检通过后，同一对话内沿用游戏记住的偶像、回忆及选项，不再重复做首检或预读 AP。用当前帧 OCR 定位开局按钮，保留跨设备进度等保护（开局只按页面类型点一次，点前重截一帧比对，过渡帧上不补点）。遇到已识别的 AP 不足弹窗，直接执行 `refill <局号>`，只用 APドリンク。补充失败就停下来诊断。确认实际进入育成后，执行 `playing <局号>`。
3. [VEIL] 秦谷美玲首检后在后台常驻运行 `watch`（整局只启动一次，不用重启）：进入 `playing` 后自动开始，下一局也会接续；只跟一局时可指定 `watch <局号>`。连点间隔默认 0.2s（`conf/batch-rules.json` 的 `watch.tap_gap`；实际约 0.39s/下）。被动页面（剧情、过场、获得动画、加载）点左上角 `(12,12)`；授業自动点蓝（Da）→ 分支第一项 → 确认强气换卡 → 训练员台词；公开课只点红（Vo）；剧情、礼物箱等有专门点击位置的过场使用 `quick_page` 的坐标。**前六周固定流程**也由 watch 自己做（`tools/batch_prep.py`，规则见下文「周回模式默认规则」的 `prep` 段）：行动页选差し入れ、最后一天进相談（`shop-auto` 后「終了」）、差し入れ选饮料 / 选技能卡、授業换卡两个阶段、「受け取らない」确认（也认 P 道具「レッスン終了時…Pドリンクを獲得」的饮料页，规则相同）、考前说明页：倍率演出时不点不停，「タップして次へ」出来后点 `(360,300)` 进入考试（watch 自己判，不再停「考试中：優勝条件」），考前「現在順位」页按「タップして次へ」的文字位置点；做完打印 `{"action":"prep","done":…}` 并已自动记账，代理不要再 `ledger-edit` 重复记。考试结果页先点一次「次へ」，晋级直接走，敗退弹「再挑戦確認」才停。剧情 SKIP 要白字模板和 OCR（「早送り」+ ログ / AUTO / SKIP）都对上才点，且不盲点重复（清单 4：模板在授業分支页淡入帧上误中，点到饮料栏第 2 格）。事件 / 公開レッスン 等直接给的饮料只有获得演出、不经过选择页：watch 认出后记账并打印 `{"action":"drink_acquired","drink":…,"ledger":…}`（`added` 已记；`choice` / `dup` 是选择页或商店那一次的演出，已记过；`full` 账本栏满、和实机对不上，用 `ledger --read-drinks` 核对）。批量工具的命令（`exam`、`customize`、`shop-auto`、`change-pick`、`settle` 等）执行时持有 `reports/batches/.lock`，watch 会等锁、命令结束后自动接着推进；代理手动点屏幕也要先拿这把锁（`fcntl.flock(open("reports/batches/.lock","a"), LOCK_EX)`），不用停 watch。`burst <局号>` 与常驻用同一套规则，只是最多点八下。

**停点（`tools/batch_hif.py` 的 `HOLD_PATTERNS`）**：每一步整帧 OCR，命中下列页面就不点：换卡阶段 1 / 2、差し入れ选饮料 / 选技能卡、任何「選んでください / 選択してください」、考试（含「残りターツ」这类误读）、考试结果 / 再挑戦、相談和商店（强化删除、交换确认）、轮间客制化、领取选择（受け取る / 受け取らない）、饮料栏详情 / 丢弃、确认框（キャンセル / はい / 決定）、结算回忆、首页 / 开局、本战开始，以及 fallback 页面、牌组一览、考试前说明、没走固定路线的行动页（相談、休む、最后一天）。`watch` 连续 3 次读到同一个停点就打印一行 `{"action": "hold", "reason": "…"}`（没走固定路线的行动页还要持续 `watch.action_hold_s` 秒，默认 10：首日淡入帧会误停），**不退出**也不再点这一页（`watch.stay`；设 false 或 `HIRO_WATCH_STAY=0` 恢复旧行为：退出码 3）。画面一变就打印 `{"action": "resume"}` 并继续推进。代理用 Monitor 盯日志，每个停点一条通知，例如 `tail -n 0 -F reports/live/watch-<批次>.log reports/live/watch-<批次>.err | grep -E --line-buffered '"hold"|"resume"|"prep"|Traceback|Error|prep 失败'`（Monitor 最长 30 分钟，到期重挂）；不要靠定时看图。`burst` 返回 `hold`。领取选择、考试中、差し入れ选饮料 / 选技能卡这四类停点在确认的那几轮里仍点 `(12,12)`，是获得动画就顺手跳过（`watch.tap_through_holds`）。这套规则用两局实机 305 帧做过全局回放（被动页面 29 帧点角落，其余全部停下），回归用例在 `tests/test_batch_route.py`。
4. 在 R1、轮间准备、R2 等转换点执行 `checkpoint <局号> --note '<阶段、下一步、日志或证据路径>'`。R2 结算页记录分数后，执行 `settle <局号> --result '<分数、名次或证据路径>'`。批量结算默认用掉画面明确显示的可用再生成次数，并按交接提示词的回忆优先级挑（`tools/batch_memory.py`：エンターテイナー+ パラメータ+12、インフルエンサー+ 強気に変更、仕切り直し+ 消費体力減少+2、巻き返し+ パラメータ値増加+1 且已删一次性限制；同名普通版不算）。每份回忆的评估记进结果的 `memories`，记账时存进该局记录。出现「再生成前 / 再生成後」挑选页时选命中的一边；所有版本都没命中时按 `memory.no_hit`（默认 `first`：选第一个即再生成前，不唤醒代理）；认不出标签和保留按钮时停下交代理（`choice` 里有各版本的评估）。「メモリー確定確認」框按标题条偏移点「生成する」，标题条停稳才点、没关就补点，`settle` 主循环也会按文字补点。还没见过挑选页时，当前回忆已命中就不再再生成（不确定再生成会不会直接替换掉它）。若出现确认页，只确认明确标明免费、使用再生成次数或持有再生成券的操作。认不清次数、费用或页面时停住，核对后可重跑同一命令。
5. 回到首页即记账，省略回忆库存前后数量核对。还有剩余局数时，先将下一局的 `opening` 写入磁盘，再点首页「プロデュース」并推进可识别的 H.I.F 本战开局页。保护弹窗和无法确认的页面交回代理按开局规程处理；最终开始确认页按 `open.auto_start`：默认每批第一局由代理核对后手点，之后的重复局自动点「プロデュース開始」（有弹窗或危险字样时不点）。开局遇到明确的 AP 不足弹窗时自动调用现有 APドリンク 流程，补充失败则停下。需要继续导航时可用 `open <局号>`。达到总次数后停在首页。若由代理手工完成收尾，确认已回首页后仍可用 `complete` 补记。

对话压缩或工具中断后，先读批次文件、路线和最近的 checkpoint。已有未结算局就按当前页面续跑原局；如果中断发生在结算和记账之间，先用当前首页和结算证据补记，别用新开局试探。常规截图和完整 OCR 留在本机，回传阶段、异常、分数及证据路径。若重新登录、手动改变编成或设置，暂停这批并重新核对发生变化的内容。


## 周回模式默认规则（conf/batch-rules.json）

所有默认选择都列在 `conf/batch-rules.json`（本机文件，`conf/` 不进仓库；没有这个文件时用 `tools/batch_rules.py` 里的 `DEFAULTS`，`write_defaults()` 可重新生成一份）。每次用到时重读，改完下一步就生效；`HIRO_BATCH_RULES` 可换路径，`HIRO_WATCH_TAP_GAP` 等环境变量仍可临时覆盖。

| 段 | 键 | 默认 | 作用 |
|---|---|---|---|
| watch | `tap_gap` | 0.2 | 连点间隔。实测 0.2 → 约 0.39s/下，0.4 → 约 0.59s/下，0.2 未见漏点误点 |
| watch | `stay` | true | 停点不退出，打印一行 `hold`，画面一变（代理处理完）自动继续；代理用 Monitor 盯 hold 行 |
| watch | `tap_through_holds` | 领取选择 等 4 类 | 这几类停点确认期间仍点 (12,12)，是获得动画就顺手跳过 |
| watch | `result_next_first` | true | 考试结果页先点一次「次へ」：晋级没有弹窗直接走，敗退弹「再挑戦確認」才停 |
| open | `auto_start` | repeat | 开局确认页「プロデュース開始」：`repeat` = 每批第一局由代理核对后手点，之后的重复局没有弹窗、没有破棄 / 别的设备 / 再開 / 付费字样时自动点；`true` / `false` = 每局都自动 / 都手点。别的设备有进度、AP 不足都以弹窗出现，有弹窗一律不点 |
| prep | `enabled` | true | 前六周固定流程（`tools/batch_prep.py`），watch 自己做完不唤醒代理 |
| prep | `action` / `last_day` | 差し入れ / 相談 | 行动页永远选差し入れ，只剩相談时选相談 |
| prep | `consult_shop` | true | 相談里先 `shop-auto` 再「終了」 |
| prep | `drink_priority` / `drink_fallback` | センブリソーダ… / rightmost | 差し入れ选饮料：逐个点开读名字按表选；都不在表里选最右（`hold` = 停下） |
| prep | `card_prefer` / `card_avoid` | 空 | 差し入れ选技能卡：按顺序选第一张命中的（卡名带不带 + 都算） |
| prep | `card_fallback` / `card_column` | once / 3 | 没命中时一次性卡优先，第 3 张是一次性就选它；`hold` = 停下 |
| prep | `change_in` / `change_column` | once / 3 | 换卡阶段 1：一次性卡优先，第 3 列优先 |
| prep | `change_out` / `change_out_swapped` / `change_out_duplicate` | 立ち回りの基本 → 表現の基本 → アピールの基本 / true / true | 换卡阶段 2：先换出 N 卡，再换出本局之前从 N 卡换进来的牌，再换出同名重复卡里没客制化的那张；客制化过的卡一律不换，都没有就停下 |
| prep | `exam_briefing` | true | 考前说明页（優勝条件 + タップして次へ）点 `(360,300)` 进入考试（watch 直接判，倍率演出时等），出牌页再停下交给代理跑 `exam` |
| interval | `customize` / `shop_auto` | インフルエンサー+ 強気追加；巻き返し+ 成長追加（限已制限削除） | 轮间客制化（代理按这里执行） |
| shop | `high_value` | ブーストエキス / センブリソーダ / 初星ホエイプロテイン | `shop-auto` 只买这些 |
| memory | `no_hit` | first | 回忆所有版本都没命中优先项：选第一个（再生成前），不唤醒代理；`hold` = 停下 |
| retry | `on_defeat` | hold | 敗退后「再挑戦確認」停下交给使用者（プロデュース終了 = 失败，不自动点） |

## 授業换卡（セレクトチェンジ）

不要逐张点开卡看详情。先 `change-scan <局号>`：
- 阶段 1（选换入的新卡）一帧读完候选，返回每列的卡名、强化和是否「レッスン中1回」（主数据）。
- 阶段 2（选换出的原卡）从上往下滑一遍，拼出整副牌组的行列表，存到 `reports/live/deck-list/change-<批次>-<局号>-<时间>.json`，打印 `r<行>: c<列> 卡名+（1回） | …` 简表，然后滑回顶部。认不出的格写 `?`，只有决策要用到这几格时才点开看。

再按行列点：阶段 1 用 `change-pick <局号> --col <列>`（点候选并点「次へ」）；阶段 2 用 `change-pick <局号> --row <行> --col <列>`，工具滑到目标所在屏、按当前屏认出的卡对齐行号后点选，并读选中框核对。核对通过时加 `--commit` 会点「チェンジ」。实机上点「チェンジ」后直接出「…にチェンジしました」，没有「決定」确认框；`change-pick` 报「确认框未出现」时先看画面，换卡多半已经成功，用 `ledger-edit --change` 补账。当前屏对不上扫描表（牌组变了）、选中框对不上时都会停下，不点「チェンジ」。

换入的卡继承换出那张的强化：换出「X+」时，换入的卡在牌组里也带「+」（实机两局：忍耐力 → 忍耐力+、オープニングアクト → オープニングアクト+），记账按这个来，不按阶段 1 候选的强化读数。点了「チェンジ」之后账本记不上（比如账本卡名和画面差一个「+」又有两种强化等级）不会抛错丢账：`change-pick` 结果里给 `ledger_todo`，watch 固定流程的 prep 行写成「…；账本待补：…」。看到就核对牌组一览，按提示用 `ledger-edit --change` 补记。

## 固定按钮与画面稳定

- **按钮表** `src/hiro/produce/hif_buttons.py`：本战几乎所有界面的固定按钮（720x1280），按位置命名、同一位置只写一次，注释列出用到它的页面。来源是使用者整理的本战界面截图（2026-11-07）和仓库已有实测，两者误差约 10px。表里没有的页面一直点 `CORNER (12,12)` 快进；不够保险时点 `BAR_GAP (386,1200)`（底栏第 4 格饮料和行动记录图标之间的空缺，考试 / 行动页都没有按钮）。花钱、不可撤销的按钮只给位置，调用前照旧文字核对。
- **补 AP**：批量工具用 `ap_refill.refill_fast`：按固定位置隔 0.8s 点三下（「AP不足」回復する → 「AP回復」APドリンク 使う → 确认框 回復する），喝 1 瓶回到 H.I.F 首页。第 2 下前只局部 OCR 那一行，必须是 APドリンク、没有ジュエル才点；否则点「閉じる」停下。主循环 `run_hif` 仍用原来逐步 OCR 的 `refill`。
- **各模块坐标**：商店、客制化、换卡、考试、回忆、恢复等模块的点击坐标都改为从按钮表取；同一个按钮原来写法不同的（如确认键 500 / 518 / 520）统一成表里的值。
- **少做 OCR**（整帧 OCR 一次约 0.27s，读一条带约 0.07s；每次调用有约 0.05s 固定开销，所以分几条带多次读反而更慢，只能少读）：
  - `watch`（`OcrGate`）：画面在动、上一步是被动页、没有弹窗，且距上次 OCR 不到 1.5s 时不读，照上一步点；同一画面沿用上次结果（停点连续确认 3 次，后两次不读）；最多 1.5s 完整读一次，停点页最晚 1.5s 内认出。
  - `settle` 前段（使用者 2026-11-07）：结果页点完「次へ」到回忆页之间不做 OCR 判页，用 `burst` / `watch` 同一套规则推进（偶像名片「TAPで次へ」、优胜 LIVE 全屏 / 跳过 / 回竖屏），推到「结算回忆」停点或 300s 后才进下面的回忆流程；停在「考试结果」（结果页 / 再挑戦確認）就交回代理。
  - `settle`：回忆定下后只点 (360,1170)，有弹窗（像素）、底栏局部 OCR 认到「ホーム」、或连点 4 下画面不变时才整帧读。
  - 客制化：同一画面沿用 OCR，切页中途（画面在变）不读；点「実行する」后只读提示那一条带，看到提示才整帧读一次。
  - 商店 / 轮间：轮间标题、体力只读那一小块（405 帧回放：标题结果一致，体力多读出 4 张整帧 OCR 漏掉的）；残留确认框先看像素标题条再 OCR；`Run.ocr` 同一张截图只读一次（不按「画面差不多」沿用，避免 P 点、「交換済」这类小变化被忽略）。
- **画面稳定** `src/hiro/vision/stable.py`：只采几个界面元素位置的小块（缩成 8×8 灰度）比前后帧，连续 2 帧变化都 < 1.5 就算稳定，避开一直在动的背景；比 OCR 快，也能看出淡入。等待期间可以顺便点快进。

## LIVE 与回忆再生成

- **考试结果之后的过场**：R1、R2 的结果页版式一样（分数 / 名次、再挑戦、次へ）。之后的名次页、スター性獲得、P 道具获得都能一直点左上角 `(12,12)` 过去（使用者实测）。再挑戦仍要文字核对只用免费次数 / 再挑戦チケット。

## 回忆栏与本局账本

本战不靠一路识别牌组和饮料，而是靠账本：
- **回忆栏**：每份回忆第一次打本战时，在开局用牌组一览核对整副牌组，写成清单 JSON（同 `deck-base` 格式），执行 `memory-save --memory <回忆名> --deck <JSON>`，存进 `reports/memories/<回忆名>.json`。之后所有批次复用，不用再核对。
- **本局账本**：每局开局 `memory-load <局号> --memory <回忆名> [--drinks 第1格,第2格,…]` 从回忆栏载入，之后每次变动记一条：
  - 自动记：`change-pick` 阶段 1 记下换入的卡，阶段 2 `--commit` 成功后记「换出 → 换入」；`shop-buy` 记进最左空格；`drink-drop` / `drink-overflow` 去掉那格并往左挤；`exam` 打完按考试里喝掉的饮料更新饮料栏。
  - 手动记（自动记不到的）：`ledger-edit <局号>` 的 `--add 卡名 --once/--not-once`（课程拿卡等）、`--remove`、`--change 旧 新`、`--upgrade`、`--drink-add` / `--drink-remove 格号` / `--drink-set 整栏`、`--rebound-repeatable true|false`，`--why` 写来由或证据。
- `ledger <局号>` 看账本；加 `--read-drinks` 只读核对实机饮料栏，加 `--log` 看逐条记录。
- `exam` 没给 `--deck` 时用账本的牌组；考试里某格饮料读不清时按账本补。

### 回忆能力（メモリーアビリティ）

一份回忆从四张回忆卡各继承一项能力，本战每场考试（R1、R2 各一场）重新计次，「〜使用後」触发、重複発動不可。效果按触发卡查主数据（`hiro.brain.memory_ability`，115 张卡各只有一项）：
- `draw`：再动一次并抽一张；`play`：只再动一次；`sleep`：从山札或捨札删一张眠気。
- 次数是主数据的「以降N回まで」，多数 1 次。

读法：考试开局状态栏指针下面那排带「N回」的卡面菱形，每个就是一项能力，按卡面认触发卡（只在触发卡里比）。用掉的能力图标会消失。
- `exam` 每轮开局自动读，读到的写进本局账本和回忆栏（回忆栏已记且不同时不覆盖，结果里 `abilities_mismatch` 给出差异）。
- 也可在考试开局手动 `memory-abilities <局号>` 读一次（`--overwrite` 覆盖回忆栏）。
- 考试中打出触发卡后：`draw` / `play` 出牌次数 +1，`sleep` 从牌堆账里删一张眠気（山札、捨札都有时记成位置未知），然后该项次数减一、用完取否。清牌时带「再动」能力的牌算多一次出牌、带「抽牌」的算即时抽牌、带「删眠気」的同分优先。

## 商店与饮料

- `shop-scan <局号>`：相談或轮间主画面，读货架上的饮料，`buy` 列出没买过的高价值三种（ブーストエキス、センブリソーダ、初星ホエイプロテイン）的格号。
- `shop-buy <局号> --index <格号>`：按固定像素买（点格 → 交換する → 核对确认框里的商品 → 交換 → 每 0.4 秒点固定位置跳过获得动画），成功后自动记账。账本饮料栏满时拒绝，先丢一瓶。
- `shop-refresh <局号>`：用 P 刷新货架后重读；确认框要ジュエル就取消。
- `drink-drop <局号> --slot <1–4>`：培育页按固定像素丢饮料栏第 N 格（格子 → 詳細 → 捨てる → はい）。
- `drink-overflow <局号> --discard <N>`：饮料溢出页丢已有的第 N 瓶（从上往下），收下新的。

## 轮间客制化（特別指導）

实机要点（第一局本战轮间）：点「実行する」后没有「実行確認」框，直接出「…をカスタマイズしました」提示，工具看到提示就算成功（有确认框时也会点）。做完游戏停在菜单页，工具会一路退回轮间主画面（菜单「もどる」→ 选卡页「終了 / もどる」，每步核对画面、没变就补点；退不回去时结果里给 `why`），下一项从轮间重新进；从选卡页开始时先滑回顶部。选中卡后各菜单项都标「カスタマイズ上限」= 已做满，直接报出来不再进菜单。等切页 / 提示时每轮点左上角 (12,12) 加速动画。点格子后详情栏卡名没变 = 这一下被丢，补点一次。实测一项 7–19 秒（以前约 6 分钟）。

`shop-auto <局号> [--max-refresh N]`：一条命令补给——读货架、买没买过的高价值饮料、P 够就刷新再读，直到账本饮料栏满 / P 不够刷新 / 到上限（自动记账）。同一进程里循环，比 scan / buy / refresh 分开调用快（识别图库只加载一次，也没有代理往返）。相談页没有刷新价格时只买不刷。P 点用游戏数字读取器读左上一小块（约 30ms，比整帧 OCR 准：两局 44 帧里整帧读错 3 次、单个「0」读不出）；循环里按价格记账推算 P，和画面读数不一致时记一条 `p_mismatch` 并以画面为准。刷新价格按次数固定上涨：10、10、20、30、40、50（封顶）。`shop-auto` 以画面上读到的价格为起点按价目表推下一次的价格，读不到时用推算值，对不上记 `refresh_price_mismatch`。本局轮间 `shop-auto` 第一次刷新就是 50，是因为使用者在这次轮间里已经手动刷新过；所以起点仍以画面为准（同一次商店里可能已经刷过）。

`deck-sync <局号> [--why <说明>]`（使用者 2026-11-07，漏记兜底）：在有牌组按钮的培育页（相談 / 选行动页 / 轮间）打开「所持スキルカード」一览整副读一遍，和账本对账：账本漏记的补上（一次性按主数据），同名只差「+」的按画面改强化，账本多出来的只记「账本多出」不删。读不全不改账本。退出商店前记账（使用者 2026-11-07）：`shop-auto` 补给成功后自己跑一次（`shop.deck_sync`，结果在输出的 `deck_sync`）——R1 前是 watch 在最后一天相談调用的那次，R2 前是代理在轮间调用的那次；没跑成功时再手动跑。考试页拒跑（考试里的一览是分组的）。`HIRO_DECK_TEXT=1`（默认关）：一览打开后点右下「卡格 / 列表」切换 (662,967) 变成列表显示，按卡名文字 OCR 对账（`hiro.produce.deck_text`；用「スキルカード(N)」总数和分组标题张数核对读全），读完切回网格；这个读法考试页的分组一览也能用。列表版面还没实机帧，第一次跑的每屏截图存在 `reports/live/deck-list/`。watch 认出卡的获得演出时也会记（`card_acquired`：`added` 已记；`ambiguous` 账本已有同名卡，强化还是新增留给 deck-sync；`choice` 是选择页那次）。

`customize <局号> --card <卡名> --item <菜单项> [--need-maxed <已做满的项>]`：在轮间主画面或客制化选卡页执行，按固定像素点「スキルカードカスタマイズ」→ 按卡图找卡（认不出的格才点一下读上方卡名，最多滑三屏）→「カスタマイズ」→ 核对菜单页卡名 → 按名字选菜单项 →「実行する」→ 确认 → 关掉提示，回到轮间。同名多张时用 `--need-maxed` 只选那一项已做满的那张。VEIL 路线的两项：

```sh
.venv/bin/python tools/batch_hif.py --batch <批次ID> customize <局号> --card インフルエンサー+ --item 強気追加
.venv/bin/python tools/batch_hif.py --batch <批次ID> customize <局号> --card 巻き返し+ --item 成長追加 --need-maxed 制限削除
```

做了「制限削除」的巻き返し+ 会自动把账本的 `rebound_repeatable` 记成 true。

**客制化效果按主数据补（`HIRO_VEIL_CUSTOM_MASTER=1`，默认关）**：考试里按牌组清单的客制化记录给手牌补效果文字。默认只认关键词表（「強気追加」→「強気に変更」）；打开后按主数据 `ProduceCardCustomize` 的菜单名查「○○追加」类效果文字（例如インフルエンサー+「温存追加」=「次のターン、温存に変更」，原来不进账本），查不到再退回关键词表。立即效果加在牌面原文前、「次のターン / 以降」这类延后效果加在原文后。可重复客制化按覆盖算：账本里第 1 级菜单名（「成長追加」）开一条链，之后的「成長+」各升一级，牌面用最后那一级的文字（巻き返し+ 做两次是「すべてのスキルカードのパラメータ値増加+2」，不是 +3）；同名多张做到的级数不同、链没开头就升级、级数超过主数据时不猜，这一项不补。同名多张（牌组里同一张卡不止一张）只补每张都做过的项：某项做过的张数少于牌组张数时不知道手里是哪一张，不补，trace 记一条 `veil_custom_uncertain`。数值增减类（パラメータ値増加、コスト減少…）不改文字。实机打开前先用 trace 回放核对姿态 / 夜空账本。

## [VEIL] 秦谷美玲的 R1／R2 出牌

首检的 `--idol` 记录为 `i_card-skin-hmsz-3-016`。开打前在选行动页用右下方的牌组图标核对完整清单。使用同一份回忆时，用 `deck-base --deck <JSON>` 登记一次，供整个批次复用。字段如下。
